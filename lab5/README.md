## 1. Задача №3557. Бинарное дерево (вставка, поиск, удаление)

Самостоятельно реализовать дерево поиска с командами `ADD n`, `DELETE n`, `SEARCH n`, `PRINTTREE`. Повторно вставляемое число не меняет дерево. При удалении узла с двумя потомками заменять значение **максимумом из левого поддерева**.

### Входные данные

До 1000 команд, из них максимум 20 `PRINTTREE`. Для `PRINTTREE` дерево гарантированно не пустое.

### Выходные данные

Для `ADD` выводить `DONE` или `ALREADY`; для `DELETE` — `DONE` или `CANNOT`; для `SEARCH` — `YES` или `NO`. При `PRINTTREE` выполнить **симметричный обход**: сначала левое поддерево, затем значение с точками по количеству рёбер от корня, затем правое поддерево.

### Пример

**Входные данные**

```text
ADD 5
ADD 3
ADD 7
DELETE 5
PRINTTREE
```

**Выходные данные**

```text
DONE
DONE
DONE
DONE
3
.7
```

### Алгоритм

Вставка, поиск и удаление занимают `O(h)`, где `h` — высота дерева. Использован собственный класс на указателях и итеративный вывод без риска переполнить стек рекурсии.

**Решение:** [`lab5_1-4.cpp`](lab5_1-4.cpp)

## 2. Задача №757. Количество уровней дерева

Построить бинарное дерево поиска в порядке поступления чисел, пропуская повторы и **не балансируя** дерево. Вывести число уровней, считая корень первым уровнем.

### Входные данные

На вход подаются натуральные числа до заключительного `0`, сам ноль не входит. В тематическом наборе — до `10^5` чисел.

### Выходные данные

Одно целое число — количество уровней дерева.

### Пример

**Входные данные**

```text

```

**Выходные данные**

```text

```

Сначала восстанавливаем точную структуру обычного BST через декартово дерево по порядку вставки. Затем обходим вершины с глубиной. Сложность `O(N log N)`, память `O(N)`.

## Почему задачи №757–765 не решаются обычной медленной вставкой

Обычное дерево поиска, которое строится последовательно и **не балансируется**, может превратиться в длинную цепочку. При входных числах `1 2 3 ... 100000 0` вставка каждого нового числа идёт до самого нижнего узла. В сумме получается **O(N²)** — первая попытка часто слишком медленная на больших тестах.

В правильных версиях используется более быстрый способ построить **ровно такое же дерево, без балансировки**:

1. Запоминаем для каждого уникального значения номер его первого появления.
2. Упорядочиваем все значения по возрастанию ключа (это порядок симметричного обхода дерева).
3. Строим *декартово дерево* по отсортированным ключам с приоритетом «кто встретился раньше»: у корня самый ранний элемент, слева только меньшие ключи, справа только большие.
4. Полученные связи между родителями и детьми совпадают со связями при обычной последовательной вставке в BST, но построение занимает `O(N log N)` вместо `O(N²)`.

**Это не AVL и не балансировка.** Структура исходного дерева сохраняется, включая вырожденные цепочки, поэтому задачи о листьях, развилках, ветках, высоте и сбалансированности дают правильные ответы. Для обходов используются циклы со стеком, чтобы не получить `RecursionError` на глубоком дереве.

Для №3557 реализовано обычное динамическое BST: ограничение на количество команд меньше. Для №2782 требуется эффективное *онлайн*-дерево, поэтому применяется treap с поддержкой операций вставки и successor.
